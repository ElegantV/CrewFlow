## AI 助手三项升级（提交 11ff03a，已部署 ECS 并验证）

1. **SSE 流式**：`/ai/chat` 带 `Accept: text/event-stream` 时返回 SSE（`reply.hijack()` 裸写帧），事件 `delta/thinking/result/error`，上游 `stream:true` 逐帧转发；JSON 模式保留兼容测试/降级。小程序端 `services/ai.js` 用 `wx.request enableChunked` + 手写增量 UTF-8 解码（分片会切断多字节汉字）+ SSE 帧解析；旧基础库无 `onChunkReceived` 自动降级非流式。助手页 askAi 边收边上屏（replaceMessage 更新占位气泡）。
2. **AI 配置可视化**：迁移 013 建 `ai_config` 单行表（model/api_url/api_key/max_tokens/max_reply_chars/system_prompt，空值回退 .env），超管专用 `GET/PUT /api/v1/admin/ai-config`（Key 只回 `***尾4位`，PUT 不传/传空 apiKey = 保留原值）。入口：用户管理页底部「AI 设置」→ `pages/admin/ai/ai`（app.json 已注册）。
3. **回复长度 + 领域限定**：`max_reply_chars`（默认 120，30~1000 可调）双重限制——系统提示词写明"不超过 N 字" + 服务端硬截断（流式超限即 abort 上游）；默认提示词限定只答请假/调休/加班/审批/通讯录等小程序功能，无关问题（天气等）礼貌拒绝并引导发指令；超管可用 system_prompt 整体覆盖（身份说明和字数约束仍由系统追加）。

坑：ECS 部署顺序必须是**先 build 后 migrate**（容器内跑迁移，旧镜像没有新迁移文件）；本地 3000/3001 端口有 PM2 和昨天遗留的旧 dev server 占用，测接口前先 `lsof -ti :PORT` 确认。测试 18 例全过（SSE 帧/截断/角色守卫/Key 脱敏/空 Key 保留）。

**400 排查结论（d64f912 + 修复）**：`/ai/chat` 收到空请求体 `{}` 的根因是 `chatStream({messages},...)` 签名误写——调用方传数组，对数组解构得 undefined，`JSON.stringify` 丢键后只剩 `{}`。已改为 `chatStream(messages, options)`。服务端的宽容清洗 + `AI chat payload rejected` 请求体摘要日志保留（这次全靠它定位，10 分钟内闭环）。

**方案 B 落地（意图分类路由）**：新增 `POST /api/v1/ai/classify`（受控枚举 JSON 输出 + few-shot 示例 + max_tokens 60），开启深度问答时客户端 `routeByAgent` 先分类：command→runRuleFlow（规则引擎执行），chat→askAi（agent 直答）；分类失败/超时（服务端 8s）回退规则引擎。重要坑：**@fastify/rate-limit 路由级限流不设 groupId 时共享按 IP 计数器**（/chat、/classify、登录互相吃额度），已用 groupId: ai-chat/ai-classify/auth-login 隔离。ECS→微信网关偶发 20s+ 挂起（直连 0.5s），分类超时快速回退是应对手段。审计发现的残留劫持（撤销加班有什么限制吗→弹撤销列表、查询张三的加班记录→答成自己的记录）由分类器解决：chat 类提示词明确"系统查不了他人完整加班记录"。

**日期幻觉修复**：用户问"国庆节距离中秋节有几个工作日"答错（答成 2025 国庆等）——根因是系统提示词没有时间锚点，模型拿训练记忆瞎猜。已注入：北京时间当天日期/星期 + 完整 2026 法定节假日与调休上班日表（从 leave-policy.ts 导出 STATUTORY_HOLIDAYS/MAKEUP_WORKDAYS，ai.ts 聚合成区间文本）+ "下一个节假日及倒计时"。这些是计算事实，管理员的 systemPrompt 覆盖不了。生产验证："国庆节与中秋节之间共 3 个工作日（9月28/29/30）"、"下一个是中秋节还有 19 天"均正确。注意：每年国务院公布新安排后仍需同步更新 leave-policy.ts 与 config/holidays.js。
